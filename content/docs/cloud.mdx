Production is us-east-1. DNS for api.amaanworks.me is on Cloudflare and points at an Application Load Balancer. The API container listens on port 8080. TLS ends at the load balancer. The worker has no public listener.

The shape replaced a single EC2 instance that ran Docker Compose, reached through a Cloudflare tunnel, and died under one encode. The instance size was t3.micro.

## Network

Terraform in YellowBird-ops describes the VPC. The address block is 10.0.0.0/16.

| Subnet | CIDR | Zone |
| --- | --- | --- |
| Public 1 | `10.0.0.0/20` | `us-east-1a` |
| Public 2 | `10.0.16.0/20` | `us-east-1b` |
| Private 1 | `10.0.128.0/20` | `us-east-1a` |
| Private 2 | `10.0.144.0/20` | `us-east-1b` |

Public subnets use an internet gateway. S3 traffic uses a gateway VPC endpoint, com.amazonaws.us-east-1.s3, attached to the route tables. A gateway endpoint stays on the AWS network, so that traffic does not go through a NAT Gateway. The endpoint is the cost control for video bytes. Do not publish the endpoint id or the VPC id from the Terraform import blocks.

## Compute

Both services are ECS on Fargate, cluster yellowbird-cluster, desired count 1.

| Service | CPU | Memory | Port |
| --- | --- | --- | --- |
| `yellowbird-api-service` | 0.5 vCPU (`512`) | 1024 MB | 8080 |
| `yellowbird-worker-service` | 1 vCPU (`1024`) | 2048 MB | none public |

Terraform ignores changes to task_definition and desired_count on those services. The deploy workflow updates the task definition with the image it just pushed. A later terraform apply is not supposed to roll that image back.

Images are yellowbird-api and yellowbird-worker in ECR, built from deployments/Dockerfile.api and deployments/Dockerfile.worker. Tags are the git SHA and latest.

## Data and secrets

| Store | Role |
| --- | --- |
| S3 | Source files and renditions when `STORAGE_PROVIDER=s3` |
| PostgreSQL | Users, projects, media, jobs, renditions. Production moved off RDS to Neon. The URL is injected, not baked into the image |
| Redis | Upstash. `internal/queue/redis.go` turns on TLS when the address contains `upstash.io` |
| SSM Parameter Store | `DATABASE_URL`, Redis password, and `JWT_SECRET`, read by the task role at start |

The task role can `ssm:GetParameter` on the project prefix. Values stay in Parameter Store. They are not in git, and they are not in this page.

## Deploy

`.github/workflows/deploy.yaml` in the Go repo runs on push to `main`.

1. `permissions: id-token: write`. The job assumes an IAM role with GitHub's OIDC provider. There is no long-lived access key in the workflow.
2. `go test -count=1 ./...` and `go test -race ./internal/...`, with FFmpeg installed on the runner.
3. Docker build, push to ECR tagged with `github.sha`.
4. Render a new task definition and update the API and worker services.

The role name is `yellowbird-github-actions-role`. The account id is not part of this document.

## Terraform

`YellowBird-ops` is a separate repository so a docs or application change does not apply infrastructure, and an infrastructure change does not ship a new encoder. The stack wants Terraform `>= 1.10` and the AWS provider `~> 5`. State is an encrypted S3 backend that uses a lockfile. Apply it from that repo, with `terraform.tfvars` kept out of git. The example variables file is the template. The real one has credentials and resource ids.

What the API and the worker do is on [Architecture](./architecture).
