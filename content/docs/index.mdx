---
title: Overview
description: Documentation for YellowBird, a Go media pipeline. Upload, FFmpeg renditions, the HTTP API, and the worker.
---

YellowBird stores an upload in object storage and in a `media` row. The API publishes the job id on Redis. `cmd/worker` claims that id and runs FFmpeg.

The split exists because the first deployment was one `t3.micro`. A single 1080p upload exhausted memory and the kernel OOM killer froze the box, SSH included. The HTTP server and the encoder were the same process. They are now `cmd/api` and `cmd/worker`.

A video upload fans out into five jobs: a JPEG thumbnail, a 10 second preview, and H.264 MP4s at 360p, 720p, and 1080p. An image upload gets the thumbnail and the preview. There is no HLS playlist in the worker. PostgreSQL is the record of what finished. Redis only delivers work.

The workspace you sign into is a Next.js app: projects, upload, job status, and renditions. It calls `https://api.amaanworks.me`. These docs are a separate site, served at `/docs`.

| Piece | Where it lives |
| --- | --- |
| API and worker | Go module `github.com/dexisback/YellowBird` |
| Workspace | Next.js app, routes `/`, `/login`, `/register`, `/library` |
| Cloud | ECS Fargate, Terraform in `YellowBird-ops` |
