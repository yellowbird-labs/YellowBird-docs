title: API Reference
description: HTTP endpoints, authentication, and request shapes for the YellowBird API.

The API is a Gin HTTP server. The production base URL is `https://api.amaanworks.me`. All resource routes are versioned under `/api/v1`. Protected routes require an `Authorization: Bearer <token>` header.

The token is the value returned by the login endpoint — an HS256 JWT with `user_id` in the claims, valid for 24 hours. A missing `Authorization` header returns `missing auth header`. A header present but not in `Bearer <token>` form returns `invalid auth header`.

## Health check

`GET /health` sits outside the version prefix and is not authenticated. It returns a JSON object confirming the server is up.

## Authentication

Register and login are public. User list, get, and delete are also on the public router — there is no authentication middleware on the users group in the current codebase.

| Method | Path | Body |
| ------ | ---- | ---- |
| POST | `/api/v1/users/register` | `name` (2–100 chars), `email`, `password` (8–72 chars) |
| POST | `/api/v1/users/login` | `email`, `password` |

Registration responds with the created user object. A duplicate email returns `email already exists`. Passwords are stored as bcrypt hashes.

Login returns `{ "token": "...", "user": { "id", "name", "email", "created_at", "updated_at" } }`. Incorrect credentials return `invalid email or password`.

## Projects

Projects scope media uploads. All routes require a valid token. The list endpoint returns only projects owned by the authenticated user.

| Method | Path | Notes |
| ------ | ---- | ----- |
| POST | `/api/v1/projects` | Body: `name`, optional `description` |
| GET | `/api/v1/projects` | Returns the current user's projects |
| GET | `/api/v1/projects/:id` | |
| PUT | `/api/v1/projects/:id` | Body: `name`, `description` |
| DELETE | `/api/v1/projects/:id` | |

## Media

`POST /api/v1/media` and `POST /api/v1/media/upload` point to the same handler. The request body is multipart with two fields: `project_id` and `file`.

The API verifies that the project belongs to the authenticated user, streams the bytes to object storage, and writes the media row. Processing jobs are created immediately after the media row is committed. A `video/*` MIME type generates five jobs: thumbnail, preview, and H.264 transcodes at 360p, 720p, and 1080p. Any other file type receives thumbnail and preview only. The response is the media row with status `uploaded`.

Poll `GET /api/v1/media/:id` to track status transitions (`uploaded` → `processing` → `ready` or `failed`). Retrieve outputs with `GET /api/v1/renditions?media_id=<id>`.

| Method | Path | Notes |
| ------ | ---- | ----- |
| POST | `/api/v1/media` | Multipart: `project_id`, `file` |
| POST | `/api/v1/media/upload` | Same handler as above |
| GET | `/api/v1/media?project_id=` | Filter by project |
| GET | `/api/v1/media/:id` | |
| DELETE | `/api/v1/media/:id` | |

```bash
curl -X POST https://api.amaanworks.me/api/v1/media \
  -H "Authorization: Bearer $TOKEN" \
  -F "project_id=<uuid>" \
  -F "file=@video.mp4"
```

## Jobs

The upload path creates jobs automatically — you do not need to call `POST /api/v1/jobs` for normal usage. It exists if you need to trigger a specific processing task outside the standard upload flow (for example, requesting a transcode height that wasn't included initially).

| Method | Path | Notes |
| ------ | ---- | ----- |
| POST | `/api/v1/jobs` | Body: `media_id`, `type` (`thumbnail`, `preview`, `transcode`). Transcode requires `target_height` of 360, 720, or 1080 |
| GET | `/api/v1/jobs?media_id=` | |
| GET | `/api/v1/jobs/:id` | Includes `error` field when the job failed |
| DELETE | `/api/v1/jobs/:id` | |

## Renditions

Renditions are written by the worker process during encoding. The POST endpoint exists but you won't call it in normal usage.

| Method | Path | Notes |
| ------ | ---- | ----- |
| POST | `/api/v1/renditions` | Written by the worker, not the client |
| GET | `/api/v1/renditions?media_id=` | |
| GET | `/api/v1/renditions/:id` | Includes the download URL |
| DELETE | `/api/v1/renditions/:id` | |
