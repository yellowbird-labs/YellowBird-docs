---
title: Running locally
description: Start the YellowBird API and worker on your machine, connect them to a database, and point the web workspace at the local API.
---

You need Go 1.26 or newer, Docker, and FFmpeg on your `PATH`. PostgreSQL must be running before either binary starts — the Docker Compose file starts Redis but not Postgres, so you need to supply a database URL pointing at an existing instance.

Clone `github.com/dexisback/YellowBird`, copy `.env.example` to `.env`, and fill in the values. `internal/config` loads that file first, then reads the process environment on top of it. The example file sets `PORT=3000` — that's the Next.js default, not the API default. Leave `PORT` unset or set it to `8080`; the config defaults to `8080` when the variable is absent. If you run via Docker Compose, the API is always forced to port 8080 regardless.

## Environment variables

| Variable | Description |
| -------- | ----------- |
| `PORT` | API listen port. Defaults to `8080` when unset. |
| `DATABASE_URL` | Postgres connection string. Falls back to `NEON_DB` if unset. |
| `JWT_SECRET` | HMAC secret for signing and verifying login tokens. |
| `REDIS_ADDR` | `localhost:6379` on the host; `redis:6379` inside Compose. |
| `REDIS_PASSWORD` | Leave empty for the local Redis container. |
| `REDIS_DB` | Database index. Use `0`. |
| `STORAGE_PROVIDER` | `s3` for AWS S3. Anything else routes to Cloudinary. Setting `S3_BUCKET` without this variable also selects S3. |
| `S3_BUCKET` | S3 bucket name. |
| `S3_REGION` | Defaults to `us-east-1` when unset. |
| `S3_ENDPOINT` | Override the S3 endpoint for MinIO or LocalStack. |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | Optional. Omit to use the default credential chain. |
| `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` | Required when the provider is not S3. |
| `WORKER_CONCURRENCY` | Parallel FFmpeg jobs per worker process. Defaults to 4. |

## Starting the services

Bring up Redis first:

```bash
docker compose -f deployments/docker-compose.yml up -d redis
```

Then run the API and worker in separate terminals:

```bash
go run ./cmd/api
```

```bash
go run ./cmd/worker
```

Once both are up, `GET http://localhost:8080/health` returns a JSON object with status `ok`. The worker logs its concurrency on startup and creates the Redis consumer group `yellowbird-workers` if it doesn't already exist.

If you'd rather not install FFmpeg on the host, you can run everything inside containers instead:

```bash
docker compose -f deployments/docker-compose.yml up --build
```

This starts Redis, the API image, and the worker image (which bundles FFmpeg).

## Connecting the web workspace

In the `yellowbird-web` repository, set `NEXT_PUBLIC_API_URL=http://localhost:8080` and run `npm run dev`. The API's CORS allow-list includes `https://yellowbird.amaanworks.me` and localhost on ports 3000, 3001, and 5173. The Next.js dev server on port 3000 is on that list by default.
